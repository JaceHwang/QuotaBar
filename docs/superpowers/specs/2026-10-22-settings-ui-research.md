# QuotaBar 设置子页面 UI 调研与优化提案

日期：2026-10-22（Asia/Shanghai）。状态：文字提案已于2026-10-22获用户批准实施，验证证据见实施计划及项目进度。

调研阶段用户选择先给文字方案、暂不生图；随后明确要求根据本提案开发，作为本轮视觉与范围批准。已有 B 侧栏与电池角色仍为产品连续性的约束。

## 1. 结论

推荐“苹果原生分组设置 + QuotaBar 电池角色”：保留侧栏、柔和绿色选中态和电池角色；统一设置行、操作按钮和分组容器，减少重复入口和装饰线。建议先继续使用现有 AppKit，不引入新 UI 框架或改变事件检测、账户隔离、通知去重及偏好存储。

以下尺寸是本项目的建议起点，不是 Apple 强制规范；应通过三语言、浅深色、键盘、读屏和小窗口验证修正。

## 2. 四张截图及当前源码的问题

| 位置 | 观察 | 优化意图 |
| --- | --- | --- |
| 窗口 | 当前默认1040×700pt、最小960×440pt；多数页面只有顶部一块内容 | 根据内容确定合理默认尺寸，大窗口限制正文宽度，不横向拉伸全部控件 |
| 侧栏 | 图标文字间距不足；未选中项偏灰；大品牌区和较高行距让导航松散 | 图标独立固定列、稳定文字起点；普通项保持可读，禁用项才明显变淡 |
| 按钮 | 登录、取消、退出、刷新、重载均是同级灰底按钮 | 按当前状态给出主要动作；辅助操作降级；账户操作和维护操作分组 |
| 控件 | 体验开关跟随标题长度、显示开关在左、更新采用复选框 | 所有即时布尔偏好采用统一设置行，控件对齐右侧；保留正确语义与状态 |
| 线条 | 卡片边框与横向分隔线叠加；更新卡片内部首行前还有分隔线 | 取消无意义首尾横线；容器弱描边；行内分隔线缩进且低对比 |
| 表情页 | 右侧预览大小和基线不一，五状态图例与正文竞争；预览入口重复 | 设置开关成为第一操作层，图例放同项下方；每个操作只保留一个就近入口 |
| 跨页组织 | 表情页底部重复账户、外观、语言和启动设置 | 偏好归属唯一页面；如需跳转，使用轻量导航链接，不复制可编辑控件 |
| 更新页 | 信息集中左上，版本和状态层次弱 | 顶部版本状态区，下面分组开关，更新动作与结果就近展示 |
| 文案 | macOS出现“任务栏” | macOS称“菜单栏显示额度”，Windows称“托盘显示额度”，分别本地化 |

源码核对：`StandaloneCoordinator.makeSettingsWindow()` 中账户操作始终加入两排按钮，表情页再次构建其他页面的设置摘要；`QuotaUpdateController.makeSettingsView()` 添加顶部 separator 并使用原生 checkbox；`QuotaSettingsShellView` 的侧栏采用按钮手工 frame，体验开关为自绘 NSButton。可通过抽取共同设置行改进，不需要重写业务逻辑。

## 3. GitHub 调研

调研基于公开仓库说明及实际设置页源码，不声称已安装或运行这些应用。链接指向当日检查的分支文件，后续可能变化。

### Ice：导航与分组表单的首要参考

- [仓库](https://github.com/jordanbaird/Ice)
- [SettingsView.swift](https://github.com/jordanbaird/Ice/blob/main/Ice/Settings/SettingsView.swift)
- [GeneralSettingsPane.swift](https://github.com/jordanbaird/Ice/blob/main/Ice/Settings/SettingsPanes/GeneralSettingsPane.swift)

借鉴：稳定导航栅格、分组与辅助说明的层级、相关设置按状态出现。QuotaBar 不需要照搬其设置数量或直接迁移到 SwiftUI。

源码使用 NSStackView、PreferencesSection、PreferencesRow，设置行承载标题和 switch/select/button。借鉴其共同设置行组织方式，将正文、说明及控件统一布局；避免每个子页面单独调整 NSButton 的外观和间距。

## 4. 推荐视觉规范

- 视觉方向：苹果原生、清爽、克制，保留 QuotaBar 电池角色。减少大面积装饰、重阴影和卡片套卡片。
- 窗口：默认约900×650pt；建议最小约840×560pt。正文最大宽度约640pt，侧栏约190–210pt；窄窗口纵向滚动，宽窗口不把控件拉到最远端。最终尺寸以最长英文和五状态图例实测为准。
- 排版：页面标题20–22pt semibold，设置标题13pt，辅助说明11–12pt；用颜色、间距和字重共同表达层级，避免全部加粗。
- 容器：正文使用系统窗口背景，卡片使用系统内容背景；圆角10–12pt、内边距16pt、组间距20–24pt。优先采用系统语义颜色；浅深色分别核对。
- 设置行：左侧标题及可换行说明，右侧开关/选择器；简单行48–52pt，带说明约64–76pt作为起点；控件在共同尾列对齐，不随标题长度移动。
- 分隔线：只用于同组相邻项，缩进到正文起点；弱化与外边框的叠加，避免一项一个边框。
- 按钮：普通操作使用系统圆角按钮和统一 controlSize；主要动作最多一个品牌强调，其余次级按钮或文本动作。退出账户与重载各自分组，不把全部按钮变成红色或绿色。
- 开关：优先 NSSwitch 的系统绘制、焦点、键盘和可访问性；品牌绿色保留在角色与选中态，不要求开关覆盖用户系统强调色。若保留自绘，必须补齐系统行为验证，不能只画外观。
- 侧栏：固定图标区域和8pt左右图文间隔；行高32–36pt起步；标题较长时验证宽度或给出短导航名，页面标题保留完整名称。不要通过低对比灰色将普通入口画成禁用。
- 不依赖新系统专属玻璃效果；如使用原生侧栏材质，兼容减少透明度并提供不透明背景。

## 5. 四页具体改法

### 账户

账户身份卡：头像/账户图标、身份、套餐（有可靠数据时）、连接状态；更新时间降为辅助信息。不要把状态、身份和时间挤成同级三行大字。

已登录时突出“查看额度”，旁边次级“刷新”；登录只在未登录时显示，取消只在登录进行时显示；退出账号独立放在账户操作区域。重载运行时放入可展开的“故障排查”，保留说明与原有功能。没有必要新增更多诊断功能。

### 显示

分“外观”和“常驻入口”两组。主题和语言使用右对齐原生选择器；显示悬浮按钮、菜单栏显示额度、登录时启动使用相同设置行和右侧开关。保留当前所有选项，英文文案换行后不挤压控件。

### 额度表情与管理

四项开关统一右对齐。表情模式下方放34–40pt的五状态角色及短标签，作为该设置的解释，而非横向大插图。

恢复提醒下方可使用轻量示例文本或通知示意，但明确为示例；避免假通知卡片成为第二主视觉。小庆祝保留恢复角色和一个就近“预览庆祝”按钮，删除重复预览按钮。“发送测试通知”只保留一个，并说明不修改真实事件记录。Bank 的72/24小时改成清晰的辅助说明，不为装饰图标单独占一大列。

移除本页底部账户/外观/通用的可编辑复制区；原功能分别保留在账户和显示页。必要的权限拒绝提示及前往系统设置入口要可见。庆祝与系统通知的现有关联、浮窗隐藏不播放等规则不变。

### 更新

顶部显示应用小图标、QuotaBar、当前版本与结果状态，“检查更新”靠近状态；检查中显示进度并禁用重复操作。下面用两行右侧开关呈现自动检查、更新提醒，取消顶部多余横线与复选框混用。

有更新时展开版本摘要、“查看更新”主操作以及“稍后/跳过”次级动作；不改变现有官方下载和更新策略。移除侧栏底部重复“检查更新”，或改为普通“关于”入口（若本轮不做关于页，直接移除重复入口）。

## 6. 实施顺序与验收建议

1. 统一 SettingsRow/SettingsSection/ActionRow 样式与尺寸，以及设置窗口正文宽度。
2. 先完成账户/显示两页，确认原生控件层级；再收敛表情页图例与测试操作；最后更新页。
3. macOS 先验证，Windows 使用对应 WPF 原生控件复现信息层级，不模仿 macOS 窗口按钮或材质。
4. 回归：三语言、浅深色、最小窗口与大窗口、Tab/Space/读屏、主题语言即时同步、登录各状态、通知权限拒绝、更新检查中/离线/有更新，以及全部偏好持久化。
5. 视觉验收以四个真实运行子页面为准；不把概念图当实现截图。当前只形成文字提案，不声称任何新设置 UI 已实现、CI通过、实机验收或发布。

范围：视觉和组织优化；现有四个功能、默认值、事件引擎与账户隔离保持。移除重复控件不等于移除功能。具体方案获得确认后再进入产品实现。
