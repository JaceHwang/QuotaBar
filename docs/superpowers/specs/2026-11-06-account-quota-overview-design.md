# 账户与额度概览设计

用户要求将浮窗完整额度信息同步到账户页，并重新设计UI、形成开发方案及实施。用户已选择A清晰概览，原始请求授权在视觉选择后继续实施。

视觉依据为[方案A](assets/account-quota-overview-a.png)。页面采用身份/套餐/数据状态、双周期额度卡片、Token图表与Bank详情分区、账号操作及折叠故障排查。概念图数值和日期均为示例，页面使用当前账户数据。

## 信息与行为

- 复用浮窗的同一快照、当前时间和统计口径。macOS使用QuotaDetailFormatter，Windows使用Copy、TokenWindow和浮窗共用Token/Bank呈现逻辑。
- 完整展示可用周期的剩余比例、重置倒计时和绝对时间。缺少第二周期只展示单卡。
- Token显示当前额度周期的七个日点及总量，沿用现有窗口算法。图题使用“本周期Token用量”，避免把额度周期误标为滚动最近七天。无数据与真实零值分别表达。
- Bank展示可用次数、全部已提供的到期明细、缺失明细说明和Credits。条目数量不截断，外层页面可以滚动。
- 保留登录、取消登录、退出、刷新、打开额度浮窗和运行时重新加载动作。登录状态决定可见按钮，刷新期间防止重复请求。
- 离线/过期快照保留可读数值并显示状态与时间，退出或切换账号后清除旧额度。未登录及首次加载显示明确状态。

## 布局与可访问性

- 左侧设置导航沿用现有结构。仅账户页放宽至960pt阅读宽度，其他页保留640pt上限。
- 常规窗口优先展示两张额度卡片。内容宽度不足760pt时Token和Bank纵向排列，避免文字与日期被截断。最小窗口840×560可滚动访问全部内容。
- 默认窗口宽度调整至1100pt以容纳A布局。深浅主题使用语义颜色，新账户页的大号额度数字保持至少3∶1对比度，Windows高对比度使用系统画刷。
- 文本可访问且可选，比例同时有数值与进度表达。保留键盘动作、按钮可访问名称和现有三语言。

## 边界与验证

本次实现双平台账户页。读取现有运行时数据，不增加采集或持久化格式。回归覆盖单/双周期、Bank空与多条、Token无数据与零、离线过期、账号退出、三语言主题和最小窗口布局。macOS本机验收及Windows原生CI分别记录。
