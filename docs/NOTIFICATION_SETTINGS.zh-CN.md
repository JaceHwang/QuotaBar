# 提醒分类与接收渠道

固定矩阵按提醒内容选择气泡、系统通知、手机Bark推送，三个渠道独立。每行全部取消即关闭；渠道滑块总开关关闭后，对应矩阵列置灰不可编辑，保留行内选择；重新开启后恢复可编辑。新增提醒不会因升级自动开启。

| 内容 | 行为 |
| --- | --- |
| 额度偏低 | 剩余跨过10%/20%/30%或自定义1–99%整数阈值时提醒，同一周期最多一次 |
| 额度耗尽 | 任一周期从可用进入耗尽；确认恢复后可再次提醒 |
| 额度恢复 | 完整采集确认恢复后提醒；庆祝动画独立控制 |
| Bank 提前72/24小时 | 已知可用重置权益到期，两个阶段分别选择渠道，不自动兑换 |
| 软件有新版本 | 遵循跳过版本、稍后提醒；与自动检查开关独立 |

新安装默认勾选全部6类×3渠道共18项；气泡总开关默认开启，系统和手机总开关默认关闭。矩阵右上方“全选”可一次勾选全部18项（包括置灰列），不会改变总开关、阈值或暂停状态。旧设置迁移保持原有实际渠道，保留账号、Key、暂停、跳过版本、延后及提醒收据。

暂停1小时只暂停气泡。开启/重开渠道不补发历史事件；新启用Bank分类先建立库存基线。未授权系统通知或未配置Bark时显示原因，不自动改发其他渠道。Bark设置页配置Key并手动测试；服务接受请求不等于手机已展示。

额度表情与恢复庆祝独立于矩阵。预览只显示本地示例。矩阵下方“发送测试通知”按当前开启的渠道发送，不受分类勾选影响；所有渠道关闭时按钮禁用。测试不改变真实额度及业务提醒记录，手机测试使用示例内容；暂停仍影响气泡。

## 实施验收边界

用户选定A紧凑矩阵，B/C未采用。原生视图测试覆盖三语言/浅深色、18单元格及文字裁切；共享fixture覆盖54组矩阵、128组迁移及21组预警序列。设备投递、用户账号自然事件、Windows设备及长期矩阵需分别记录，不能由跨编译或服务接受替代。
