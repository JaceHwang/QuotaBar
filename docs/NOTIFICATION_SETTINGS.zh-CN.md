# 提醒分类与接收渠道

提醒矩阵按内容选择气泡、系统通知、手机推送，三个渠道独立。顶部总开关名称为“气泡通知”“系统通知”“手机推送通知”。关闭渠道后，该列勾选项及“全选”按钮置灰，已保存选择保留；重新开启不补发历史提醒。

| 内容 | 行为 |
| --- | --- |
| 额度耗尽 | 任一额度周期从可用进入耗尽；确认恢复后可再次提醒 |
| 额度恢复 | 完整采集确认恢复后提醒；庆祝动画独立控制 |
| 额度偏低 | 可增删多个1–99%整数阈值；每个阈值在每个周期内提醒一次 |
| Bank 到期提醒 | 合并为一类，可增删1–8760小时整数阈值；默认72和24小时，同批权益合并 |
| 软件有新版本 | 遵循跳过版本、稍后提醒；与自动检查开关独立 |

额度偏低紧挨 Bank 之前。两类阈值均使用可编辑标签：输入数字后回车或离开字段保存，“×”删除，“＋”添加；空白新增项在输入前不保存，Esc取消；无效或重复值不改变设置。每类最多32项，自动去重、从大到小排序。删除最后一项后该类不再触发，渠道选择保留。一次刷新跨越多个阈值时只发最紧急的一条，其他已跨阈值也视为消费，避免连发。

矩阵显示5类×3渠道，共15格。每列都有自己的“全选”，只选择当前列的全部类别，不改变其他列、总开关、阈值或暂停。新安装所有15格默认选中；气泡总开关默认开启，系统和手机总开关默认关闭。已有配置保留，旧 scalar 阈值转换为单项，旧 Bank72/24 分项渠道不同则显示“部分选中”；点击合并后的渠道格才统一该渠道，新增 Bank 阈值继承已有渠道交集，编辑数值保留原分项选择。

暂停1小时仅影响气泡。新增/编辑/重开阈值会先建立基线，不补发过去跨过的提醒；已消费状态跨重启保留。Bank 基线仅在完整合法库存上消费；不自动兑换权益。系统未授权或 Bark 未配置时不会自动改发其他渠道。

矩阵下方“发送测试通知”按已开启的总开关发送示例，不受分类勾选影响；全部总开关关闭时按钮禁用。手机 Key 在手机推送页配置；服务接受请求不等于手机已展示。额度表情和恢复庆祝独立，庆祝/气泡预览只在本地展示，不发送手机测试。测试不修改真实额度或业务提醒记录。

## 消息提醒

菜单栏、浮窗菜单和提醒设置的入口统一为“消息提醒”。默认打开“未读提醒”；“历史消息”保存全部真实消息，包括已读消息。点击一条消息查看详情后自动将该条标为已读；未读行移除后保留详情，不会自动读取下一条。“全部已读”不删除历史。窄窗口通过“返回列表”切换。

消息及已读状态保存在本机应用数据目录的 message-center.json，重启后仍可查看，不自动按数量或时间删除。多渠道接收合并为一条，预览和测试通知不进历史，重启不补发历史通知。历史正文保留产生时的快照；旧登录周期标明历史会话，按钮打开当前额度或更新页。退出登录不会清除本地历史；其他设备不共享这些记录。旧版本已退出后丢失的内存提醒无法补回。

存储异常时显示错误和重试入口，保留原文件，尚未保存的新消息仅当次可见。已读状态写入失败时继续显示未读；恢复存储后可再次点击“标为已读”。

## 验收边界

本地共享fixture、原生渲染、平台CI和实际用户设备分别记录。Windows跨编译不能替代WPF运行，手机服务接受不能替代真实手机接收；自然账号事件、长期矩阵及多屏体验另行验收。
