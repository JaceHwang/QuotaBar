# Bark 手机推送（开发候选）

Bark 手机推送尚未包含在公开 v1.2.0。此文对应开发分支，验证状态见[验收记录](validation/2026-10-23-bark-mobile-push.md)。

## 配置

1. 在 iPhone 安装 Bark，从 Bark 复制 Device Key。
2. 打开 QuotaBar 设置 → 手机推送，将 Key 输入密码框，点击“保存 Key”。请只输入 Key，不要输入完整推送 URL。
3. 点击“发送测试推送”。测试只用示例内容，即使自动手机推送关闭也可使用。
4. 确认手机收到消息后，开启“启用手机推送”。保存 Key 不会自动开启或发送。

Key 请直接在本机输入，不要粘贴到聊天、截图或 issue。已保存的 Key 不会回填到输入框；留空不会清除旧 Key。需要删除时使用“清除 Key”，自动推送随之关闭。

第一版使用固定官方服务器 `https://api.day.app/push`，不支持自建服务器、多设备或完整 URL 配置。无 Key 时不能启用。macOS 使用 Keychain，Windows 使用当前用户的 Credential Manager；系统安全存储不可用时不会降级明文保存。

## 哪些消息会发送

开启后，已确认的额度恢复、已知 Bank 权益到期、软件更新提醒可发送到手机。原有类别开关、两次查询恢复确认、Bank 72/24 小时阶段、更新跳过版本和稍后提醒仍生效。未提供的到期时间不会猜测，不新增低额度预测提醒。

手机通道独立于桌面展示方式。桌面设为关闭、浮窗隐藏、锁屏或暂停气泡时，只要应用仍运行且产生有效事件，手机通道仍处理。电脑真正休眠或应用退出期间无法查询或发送；唤醒不补发历史提醒。

本地“预览气泡”“预览庆祝”等示例不会自动发送到手机。手机页的测试按钮是独立操作，不修改真实提醒基线和去重记录。

手机请求不会改变桌面未读，不会因手机发送而提前收起气泡。桌面持续显示不意味着 iOS 通知也持续显示；手机声音、通知权限和专注模式由 Bark/iOS 控制。

## 发送状态和去重

“Bark 服务已接受”表示 HTTP 与服务业务响应均成功，不等于手机已展示。请在 iPhone 实际确认，并检查 Bark 通知权限、网络和专注模式。

每个真实事件自动尝试一次；失败、超时、429 或服务错误不会自动重试。超时可能发生在服务接受之后，因此显示“结果未知”而不冒称没有送达。用户可再次显式测试配置。

手机尝试收据与桌面记录独立且持久化。持续显示、重复刷新、重启、切换桌面渠道、启用或更换 Key 不会补发同一旧事件。软件更新明确“稍后提醒”到期可以形成新的合法提醒。状态写入失败会抑制手机发送，桌面与额度查询继续工作。

清除、关闭或更换配置会取消尚在队列或请求中的手机工作；已经交给 Bark/APNs 的通知无法保证撤回。请勿删除整个账户目录来重置提醒。

## 数据与故障排查

启用后，现有提醒标题、正文、Device Key 和固定分组/普通优先级通过 HTTPS 发往 Bark 官方服务，再由 APNs 处理。标题正文可能包含额度百分比、已知到期时间或更新摘要；不发送账户邮箱、头像、登录凭据、原始协议响应或日志。本版未配置 Bark 加密消息，不声称端到端加密。

Key 不写入普通偏好、收据或日志。安全存储失败、配置错误、网络错误等只显示本地化分类，不展示服务器原文或含凭据的异常。保留损坏收据文件用于排查，并保守抑制现有提醒，避免重复轰炸。

请同时参考[隐私说明](PRIVACY.md)、[故障排查](TROUBLESHOOTING.md)及[Bark 官方教程](https://github.com/Finb/Bark/blob/master/docs/tutorial.md)。

手机提醒收据损坏时会保留原文件、持久化恢复标记并关闭自动手机推送，避免重启重播。请在设置重新开启；开启时会抑制当前已知提醒，只接收此后的新事件。
